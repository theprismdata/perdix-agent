# 슬래시 목표 루프

`/loop`는 한 번의 모델 응답이 끝난 뒤에도 외부 검증 결과에 따라 작업을 이어 간다.
Python 서버가 실행·검증·실패 피드백·상태 기록·다음 반복·종료를 제어한다.
일반 채팅과 Build Turn의 동작은 바꾸지 않는다.

## 시작

프로젝트에 `.perdix/config.json`을 만든다. 검증 명령은 목표의 완료 기준이어야 한다.
다음은 pnpm 프로젝트의 예다.

```json
{
  "verify": {
    "commands": [
      { "name": "test", "run": "pnpm -r test", "timeout": 120 },
      { "name": "typecheck", "run": "pnpm -r typecheck", "timeout": 120 }
    ]
  },
  "loop": {
    "max_iterations": 5,
    "max_steps": 200,
    "timeout": 600,
    "max_stagnant_iterations": 3
  }
}
```

CLI에서는 해당 폴더에서 `perdix --trust-project`를 실행한다. VS Code는 기존의
작업 폴더 신뢰를 확인한 뒤 서버에 신뢰 플래그를 전달한다. `/`를 입력하고 목표 루프를
선택하거나 다음 명령을 직접 입력한다.

```text
/loop 실패하는 테스트를 고치고 전체 테스트와 타입 검사를 통과시켜줘
/loop status
/loop cancel
/loop resume
```

목표 실행 중 status와 cancel을 쓸 수 있다. Ctrl+C(CLI) 또는 중지 버튼(VS Code)도
같은 서버 취소 이벤트를 사용한다. `/loop`만 입력하면 도움말을 표시한다.
`/loop start <목표>`도 지원한다. `status`, `cancel`, `resume`을 목표로 쓰려면 start를 쓴다.

목표 루프는 세션의 현재 모드와 관계없이 실행 동안 Build 도구를 사용한다. 실행 권한은
기존 정책을 유지한다. 신뢰 플래그 자체는 도구 권한을 자동 허용하지 않는다.
대화형에서는 필요한 작업과 검증 명령을 승인한다. 헤드리스 기본 정책은 deny이므로,
쓰기나 검증에 필요한 정책을 별도로 제공하지 않으면 목표는 실패로 종료한다.

## 성공과 실패

- 모델의 완료 선언만으로 성공하지 않는다. 지정한 모든 검증 명령이 exit 0으로 끝나고
  시간 초과·취소가 없어야 `verification: passed`다.
- 검증 명령 실패 시 stdout/stderr의 마지막 각 4,000자를 다음 Turn에 전달한다.
- 반복, 전체 활성 실행 시간, 부모·자식 공유 Step 예산을 제한한다. 검증의 이름·종료 코드·
  출력이 연속으로 동일하면 `max_stagnant_iterations`에서 진전 없음으로 중단한다.
  이 기준은 보수적이다. 코드를 바꾸고 있어도 검증 출력이 같으면 중단할 수 있다.
- 권한 거부, 설정 변경, 모델 오류, 한도 소진은 성공으로 처리하지 않는다.
  검증 실패의 헤드리스 종료 코드는 1이다.
- 검증은 명령이 확인하는 범위만 증명한다. 테스트에 없는 요구사항이나 화면 품질을
  자연어 목표만으로 자동 보장하지 않는다.

## 상태와 재개

목표·검증 설정·반복 횟수·공유 Step 사용량·활성 실행 시간·피드백·종료 사유는
세션 SQLite event log에 `loop_state`로 append한다. 과거 이벤트는 수정하지 않는다.
제어 명령 응답과 진행 안내는 표준 ACP 텍스트로 표시하며, status 조회는 모델을 호출하지 않는다.

서버가 종료되면 `perdix --trust-project --resume <sessionId>`로 세션을 불러오고
`/loop resume`을 입력한다. VS Code에서는 기록에서 같은 대화를 연 뒤 재개한다.
재개는 동일 프로젝트·동일 설정만 허용하며, 누적 반복·Step·활성 실행 시간은 유지한다.
중간에 강제 종료된 반복도 시도 횟수에 포함한다. 검증 통과한 목표, 설정이 바뀐 목표,
한도가 소진된 목표는 재개하지 않고 새 목표를 시작해야 한다.

현재 범위는 사용자가 시작하는 단일 목표다. 스케줄러, 자동 worktree, 모델 리뷰어는
포함하지 않는다. 결정 기록: [ADR 0010](adr/0010-goal-loop.md).
실행 증거와 검증 범위: [목표 루프 검증 기록](goal-loop-verification.md).
