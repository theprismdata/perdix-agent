# 0025: 터미널 에이전트 팀

상태: 승인된 구현 방향

## 결정

각 CLI는 기존처럼 독립 Python 서버를 실행한다. 팀 상태는 프로젝트 절대 경로와
팀 이름으로 격리된 SQLite DB에 저장한다. DB는 기본 `~/.perdix/teams.sqlite3`이며
`--team-db`로 바꿀 수 있다. 메시지와 팀 이벤트는 append-only다. 구성원과 작업 표는
이벤트와 같은 트랜잭션에서 갱신하는 현재 상태 투영이다.

`--team`, `--member`, `--team-role`은 서버 실행 설정이다. 클라이언트는 LLM이나
작업 배정 판단을 하지 않는다. `--team-worker`는 같은 ACP 세션에서 표준
`session/prompt`를 반복한다. 서버는 대기 중인 구성원의 메시지를 기다린 뒤 작업을
실행한다. 취소는 표준 `session/cancel`을 사용한다. 새 ACP 확장은 추가하지 않는다.

리더만 작업 배정, 재배정, 팀 종료를 할 수 있다. 각 구성원은 서버에 묶인 이름으로
메시지를 보내며 이름을 도구 입력으로 사칭할 수 없다. 작업 완료는 담당자만 가능하다.
작업에 지정한 파일 범위가 진행 중인 다른 작업과 겹치면 배정을 거부한다.
이는 작업 계획의 충돌 방지이며 실제 파일 쓰기의 보안 경계는 아니다. 동시 구현은
각자의 git worktree를 쓰고 `--team-project`로 같은 팀 프로젝트를 지정한다.

메시지는 세션 event log에 넣은 다음 수신 확인한다. 확인 전 중단되면 다시 전달될 수
있으므로 메시지 ID를 포함한다. 팀 재시작은 새 팀 이름을 쓴다. 종료된 팀과 메시지는
지우지 않는다. 프로세스가 비정상 종료하면 리더가 구성원을 제거하고 작업을 재배정한다.

## 범위

로컬 머신의 터미널 협업, 공용 작업 목록, 직접 메시지, 방송, 자동 수신 실행을 제공한다.
터미널 창 자동 생성, 원격 머신 통신, 자동 git 병합은 포함하지 않는다.
