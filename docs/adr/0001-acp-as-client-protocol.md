# ADR 0001: 클라이언트↔코어 프로토콜로 ACP 채택

- 상태: 채택 (2026-10-07)

## 맥락
TS 클라이언트(TUI, VS Code)와 Python 코어 사이 프로토콜이 필요하다. 후보: ACP(JSON-RPC/stdio), HTTP+SSE(OpenCode 방식), 자체 WebSocket JSON-RPC.

## 결정
ACP를 채택한다. stdio 전송을 1차로, WebSocket을 원격 시나리오용으로 예약한다.

## 근거
- 표준이므로 Zed, Neovim 등 ACP 클라이언트가 추가 작업 없이 Perdix 코어에 연결된다.
- 권한 요청, 도구 호출 상태, diff 콘텐츠, 파일 I/O 위임(`fs/*`)이 이미 스펙에 있어 자체 설계 비용이 줄어든다.
- Python/TS 공식 SDK가 있어 양쪽 타입을 수동 유지하지 않아도 된다.

## 결과
- 멀티 클라이언트 동시 접속(한 서버, 여러 프런트엔드)은 HTTP 방식보다 불리하다. 필요해지면 서버에 HTTP 어댑터를 추가로 얹는다(코어는 변경 없음).
- 확장 기능은 `_perdix/` 접두 메서드로만 추가하고, 표준 클라이언트는 이를 무시해도 동작해야 한다.
