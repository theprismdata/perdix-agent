# ADR 0010: 슬래시 명령으로 실행하는 목표 루프

상태: 채택

## 배경

Turn의 모델·도구 반복과 별도로 목표 실행, 외부 검증, 실패 피드백, 상태 복구를
이어 주는 외부 루프가 필요하다. 클라이언트에 에이전트 판단을 넣지 않는다.

## 결정

- `/loop <목표>`, `/loop status`, `/loop cancel`, `/loop resume`을 표준
  `session/prompt`로 전달한다. `available_commands_update`로 명령을 광고한다.
- 서버 Python 하네스가 기존 TurnRunner를 Build 모드로 반복 실행한다. 한 목표 실행
  전체에 세션 락과 취소 이벤트를 유지한다. status/cancel은 실행 중에도 처리한다.
- `.perdix/config.json`의 `verify.commands`가 기계적으로 확인할 완료 기준이다.
  설정이 없거나 프로젝트가 미신뢰이면 모델과 검증 명령을 실행하지 않는다.
- 신뢰는 서버의 `--trust-project`와 기동 cwd에 한정한다. 클라이언트가 준 메타데이터로
  신뢰를 넓히지 않는다. VS Code는 신뢰된 작업 폴더를 확인한 후 플래그를 전달한다.
- 검증 명령은 기존 ExecBackend와 권한 정책을 사용한다. 설정 파일의 바이트 해시를
  고정하고 실행 중 변경되면 중단한다. 검증 통과 없이 성공 상태를 만들지 않는다.
- `loop_state` 이벤트에 목표·설정·반복·검증 결과·종료 사유를 append한다.
  SQL 스키마 변경 없이 새 이벤트 kind를 추가한다. ModelView는 이 이벤트를 무시한다.
- 반복·시간·공유 Step 예산과 동일 검증 실패 반복 제한을 둔다. 제한 도달은 실패다.
  중단된 실행은 명시적 resume으로만 재개하며, 누적 예산은 초기화하지 않는다.

## 범위

첫 버전은 사용자가 시작하는 단일 목표와 명령 기반 검증이다. 스케줄링, 자동 worktree,
모델 리뷰어, 외부 서비스 연결과 임의의 자연어 목표의 의미적 완성 보장은 포함하지 않는다.
기존 채팅과 Build Turn의 종료 규칙은 유지한다.
