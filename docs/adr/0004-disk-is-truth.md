# ADR 0004: 파일 내용의 기준은 디스크 하나이며, 에디터 저장 경로로 쓰지 않는다

- 상태: 채택 (2026-10-07)

## 맥락
VS Code 연동 시 ACP `fs/*` 위임으로 저장 안 된 버퍼를 읽거나, 에디터 API로 편집 후 저장하는 선택지가 있었다. 리뷰에서 두 문제가 확인됐다. (1) read만 버퍼를 보면 grep/bash/검증/체크포인트가 보는 디스크와 두 버전이 생긴다. (2) 에디터 저장은 `formatOnSave`와 저장 훅을 실행해 모델이 쓴 내용과 디스크 내용이 달라지고, 다음 edit의 old_string 매칭이 깨진다.

## 결정
- 읽기는 항상 디스크. 버퍼가 dirty면 경고 한 줄만 덧붙인다.
- 쓰기는 디스크에 직접. dirty 버퍼와 충돌하면 사용자에게 묻고, 승인 시 쓴 뒤 버퍼를 디스크로 되돌린다.
- 에디터 저장 API는 쓰지 않는다.

## 결과
- 열린 편집기의 undo 스택에 에이전트 편집이 남지 않는다. diff 뷰(`ide/openDiff`)로 보완한다.
- 설계 문서의 `ide/readBuffer`, `ide/applyEdit`는 `ide/getDirtyFiles`, `ide/revertFile`로 대체됐다.
