# 검증 가능한 팀 워크플로

## 워크플로 스튜디오

Gateway 상단의 입력창에 요청을 쓰고 **AI 계획 만들기**를 누르면 AI가 단계(노드)를 구성해
캔버스에 보여 준다. 단계를 클릭하면 오른쪽에서 이름·해야 할 일·담당 모델을 고치고,
단계 오른쪽의 **+** 로 다음 단계를 추가한다. 입력칸을 벗어나면 변경이 자동 반영된다.
**실행**을 누르면 수정한 내용은 새 계획으로 저장된 뒤 실행되며, 원래 AI 계획과
실행 기록은 바뀌지 않는다. 실행 중에는 각 단계에 상태가 표시되고, 끝나면
**변경 수락/거절**, 중단되면 **재개/재시도**가 나타난다.

고급 메뉴에서 단계를 직접 추가하거나 연결 관리, 목표 수정, 기존 계획 복사를 할 수 있다.
역할(분석·구현·리뷰)과 파일 범위·ID·산출물은 단계 설정의 **고급 설정**에 있다.
순환·자기 연결·중복 연결은 거절한다. 실행 중인 계획을 직접 수정하는 기능은 제공하지 않는다.
초안과 배치 좌표는 현재 탭에서 프로젝트별로 복원된다.

`/workflow plan <요청>`으로 계획을 만들고 작업 범위와 수락 조건을 확인한다.
`/workflow start <runId>`는 계획을 실행한다. 실행 상태, 검증 상태, 변경 수락 상태는
서로 다르다. 작업이 완료되어도 검증 통과나 원본 반영을 의미하지 않는다.

Gateway 대시보드에서 작업을 선택하면 **팀 진행 상황**에 작업 의존성을 표시한다.
화살표는 선행 작업에서 후행 작업으로 향한다. 담당 역할은 노드 속성이다.
노드나 작업 목록을 선택하면 파일 범위, 수락 조건, 모든 시도, 실패 이유,
산출물 경로, 변경 커밋, 검증 영수증을 확인할 수 있다.
원본 실행 기록 링크는 선택한 Gateway 작업의 기록으로 이동한다.

확대·축소·맞춤 보기와 네 방향 이동 버튼을 제공한다. 그래프 빈 공간을 마우스로
끌어 이동할 수도 있다. 노드는 Tab으로 접근하고 방향키로 이동하며 Enter 또는
Space로 선택한다. 좁은 화면과 보조 기술에서는 같은 내용을 가진 작업 목록을 사용한다.

**수동 팀 배정** 보기는 등록된 프로젝트의 기존 팀을 읽기 전용으로 표시한다.
점선은 팀원과 배정된 작업 사이의 관계다. 작업 간 의존성을 추정하거나 수동 완료
보고를 검증 통과로 표시하지 않는다. 프로젝트 선택을 바꾸면 해당 프로젝트의 팀을 조회한다.

화면은 인증된 snapshot과 event cursor를 주기적으로 조회한다. 중복 이벤트를 무시하고
새 이벤트나 누락 구간이 있으면 권위 있는 snapshot을 다시 읽는다. 네트워크 실패 시
마지막 관측 상태를 유지하고 재연결 안내를 표시한다. 화면을 닫아도 실행은 유지된다.

`/workflow status <runId>`로 상태를 읽고, 중단 뒤에는 `/workflow resume <runId>`로
재개를 요청한다. 결과가 불명확한 작업은 자동으로 재실행하지 않는다.
`/workflow retry <runId> <taskId>`는 명시적인 재시도 요청이다.
`/workflow accept <runId>`는 검증된 동일 변경을 원본에 반영하도록 요청한다.
`/workflow reject <runId>`는 변경을 거절한다. 변경 수락은 자동으로 일어나지 않는다.

## 실행 준비와 제한

현재 워크플로는 구현 작업이 최소 하나 포함된 변경·검증용 계획을 지원한다.
구조 비교나 해결책 설명처럼 분석만 필요한 요청은 `/workflow plan` 없이 일반 프롬프트로 보낸다.
여러 저장소를 담은 상위 폴더에서는 일반 대화를 사용할 수 있지만 워크플로 계획은 만들 수 없다.

원본은 깨끗한 로컬 Git 저장소여야 하며 기준 커밋과 브랜치가 있어야 한다.
Gateway 설정의 `projects.<이름>.cwd`에 저장소 루트를 등록하고 `trust_project: true`로
신뢰를 명시한다. 검증 명령은 프로젝트의 `.perdix/config.json`에 등록한다.

```json
{"verify":{"commands":[{"name":"테스트","run":"python -m pytest","timeout":120}]}}
```

검증 명령이 없으면 검증 통과로 간주하지 않는다. 계획 이후 설정이나 원본 HEAD가
바뀌거나 원본에 미커밋 변경이 생기면 실행·수락이 거절될 수 있다.
기본 한도는 최대 20개 작업, 동시 작업 2개, 수정 반복 2회, 전체 모델 Step 200회,
실행 시간 1800초다. 재개나 재시도로 예산을 초기화하지 않는다.

Gateway에서 계획 실행·재개 요청·선택 작업 재시도·검증된 변경 수락·변경 거절을
버튼으로 요청할 수 있다. 변경 수락은 원본 반영 확인 창을 거친다. 실행 중 충돌한
제어 요청은 서버가 거절하며 오류를 버튼 아래에 표시한다. 권한 요청은 기존 작업
상세의 승인 카드에서 처리한다. 그래프는 Git worktree를 보안 샌드박스로 보장하지 않는다.
