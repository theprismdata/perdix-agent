# Perdix CLI 디자인 계약

## 1. 분위기와 정체성
기존 Ink 터미널 UI를 유지한다. 대화와 도구 결과가 본문이고 입력창 바로 위에
현재 처리 상태를 둔다. 실행 종료 안내는 대화 기록에도 남긴다.

## 2. 색상
`src/ui/theme.ts`의 기존 토큰을 사용한다. 기본 텍스트는 터미널 전경색,
진행은 `accent`, 실패는 `error`, 주의는 `warning`, 완료 도구는 `success`다.
색상만으로 상태를 구분하지 않고 한국어 상태명을 함께 표시한다.

## 3. 글꼴
터미널의 고정폭 글꼴과 글자 크기를 따른다. 진행 상태는 일반 굵기,
응답 본문은 기존 Transcript와 같은 글자 크기다. 웹용 폰트나 DOM 도구는 사용하지 않는다.

## 4. 간격과 배치
기존 세로 Box 스택을 유지한다. 도구 본문 들여쓰기는 2칸, 입력창은 기존 round 테두리다.
진행 상태는 독립 행으로 줄바꿈하며 모델명이나 컨텍스트 통계 때문에 사라지지 않는다.
기록 스크롤은 터미널이 담당한다. 40·80·160열에서 상태와 긴 제목을 확인한다.

## 5. 컴포넌트
- Transcript: 사용자·답변·오류·종료 안내, 정착한 기록은 Static으로 보존한다.
- ToolCard: 대기·실행 중·완료·실패를 아이콘과 문구로 표시한다. 기존 결과 펼침을 유지한다.
- RequestProgress: 준비·모델 응답 대기·도구 대기·도구 실행·승인 대기·종료 결과를 표시한다.
  진행 중에는 경과 시간과 취소 키를 표시한다. 30초간 이벤트가 없으면 수신 대기 안내를 덧붙인다.
- InputBox·StatusBar: 기존 키보드 조작과 모드·모델·컨텍스트 표시를 유지한다.

## 6. 동작
기존 스피너 외에 움직이는 장식을 추가하지 않는다. 경과 시간은 1초마다 갱신한다.
무응답 시간을 실패로 추정하지 않는다. 완료 안내는 실제 종료 이벤트로만 결정한다.

## 7. 표면
터미널 배경을 그대로 사용하고 새 배경색·그림자·테두리를 추가하지 않는다.

## 8. 접근성과 검증 범위
상태는 한국어 텍스트로도 읽힌다. Ctrl+C 취소, Ctrl+O 도구 결과 펼침을 유지한다.
Ink의 CJK 폭 계산과 줄바꿈을 사용한다. 터미널 배경·글꼴 대비는 사용자 설정에 의존한다.
이번 변경은 CLI에 한정하고 Webview는 기존 표시 경로를 유지한다.

## 9. Hermes 평가판

`--tui hermes`는 Hermes 원본 `AppLayout`, composer, transcript, overlay와
자체 Ink 렌더러를 사용한다. 색상과 간격은 원본 `theme.ts` 및 `config/` 토큰을 따른다.
전체 화면의 대화 본문은 원본 ScrollBox가 스크롤을 소유하고 입력창·상태줄은 고정한다.
Perdix 식별은 연결 시 전달하는 skin branding과 평가판 안내에 둔다.
권한 화면의 선택지는 ACP가 실제로 광고한 승인·거절 종류로 제한한다.
새 디자인이나 장식은 추가하지 않는다. 원본 UI의 영어 문구는 이번 평가에서 허용한다.
40·80·120열과 밝은/어두운 테마에서 입력·응답·권한·복원 상태를 검증한다.
DOM 전용 react-grab/react-scan과 Lighthouse는 터미널 렌더러에 적용하지 않는다.

Hermes 상태줄은 모델 앞에 `에이전트: chat|plan|build`를 표시한다. 서버의 현재
모드를 사용하며 연결 전에는 값을 추측하지 않는다. 기존 모델 영역의 폭 계산과
색상 토큰을 재사용하고 자동·수동 전환 및 세션 복원 후 즉시 갱신한다.

`/assign`은 기존 ModelPicker의 토큰·검색·스크롤을 재사용한다. 에이전트 목록에서
방향키와 Enter로 역할을 고르고 OpenRouter 모델을 입력 검색해 Enter로 저장한다.
Esc는 검색 초기화·이전 단계·취소 순서로 동작한다. 조회 중·오류는 기존 overlay
텍스트로 표시한다. 역할 단계 제목과 저장 결과는 한국어다. 서버 작업 중에는 저장을 거절한다.
